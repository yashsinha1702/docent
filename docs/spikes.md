# Spikes

Every experiment that retired (or confirmed) a risk from the plan's assumptions register, with the result. Machine: macOS (Apple Silicon), Claude Code 2.1.302, Node 22.23.3.

## 2026-10-18 (day 0)

| Id | Claim | Result |
| --- | --- | --- |
| A1 | node-pty builds on this Mac | **Pass.** `node-pty@1.1.0` ships prebuilds for `darwin-arm64`, `darwin-x64`, `win32-x64`, `win32-arm64`. Its `prebuilds/*/spawn-helper` arrives without the executable bit, so every spawn fails with `posix_spawnp failed` until `chmod +x` (now done in `scripts/postinstall.mjs`). A from-source rebuild (`npm rebuild node-pty`) produces an executable helper. |
| A1 (Electron) | node-pty runs inside Electron | **Pass.** Electron 44.9.0 (Node 24.22, ABI 149); `@electron/rebuild -w node-pty` then `pty.spawn('/bin/zsh')` in the main process printed `PTY_OK arm64`. Launch the Electron binary directly in scripts: `npx electron` hung in this environment. |
| A2 | the `claude` TUI runs in node-pty | **Pass (unstyled check).** `claude --debug --plugin-dir …` in a 120×40 pty rendered, took keystrokes, ran `/pairwatch status` and `/ide`. Startup probes seen: `OSC 7501;?` (status protocol, must be answered), `CSI ?u` (kitty keyboard query), DA1 (`CSI c`), bracketed paste (`?2004h`), mouse modes (`?1000-1006`), `OSC 0;` titles. Not seen: OSC 9 / OSC 777 notifications, `?2026` synchronized output. |
| A8 | Pairwatch's hooks module loads for this account | **Pass, with a delay.** First log lines say `hooks module pairwatch@inline not loaded: rollout flag (tengu_plugin_hooks_modules) is off (disk cache)`; ~10 s later `the rollout flag answered on … the flag payload landed (375ms)` and the mod loaded late. `/pairwatch status` then answered (pump ticking, status line `pairwatch: idle`). The same happened through the `dev-mods` hot-reload path. The disk cache can lag: Docent must not conclude "Pairwatch is off" from the first seconds of a session. |
| A9 | the viewer port | **Finding.** Port 7979 on this Mac is held by a VS Code `Code Helper (Plugin)` process (a Remote-SSH port forward), so the mod logged `port 7979 is taken` and gave up. Docent's host mode must pick its own port and pass it to the mod: the debug log reads the mod's options from `pluginConfigs["pairwatch" or "pairwatch@inline"].options` in user, `--settings` or managed settings, so `--settings '{"pluginConfigs":{"pairwatch@inline":{"options":{"viewerPort":<port>}}}}'` is the lever. |
| A14 | OSC payloads | **Partial.** `OSC 7501;?` is sent once at startup. OSC 9/777 are not sent to an unknown `TERM_PROGRAM`, as the integration report predicted. |
| A16 | package versions | **Done.** Latest on 2026-10-18: electron 44.9.0, electron-vite 6.0.0, electron-builder 26.15.3, @electron/rebuild 4.2.1, node-pty 1.1.0, @xterm/xterm 6.0.0 (+ fit 0.11.0, web-links 0.12.0, unicode11 0.9.0, clipboard 0.2.0), codemirror 6.0.2, @codemirror/view 6.43.14, @codemirror/state 6.7.6, @codemirror/merge 6.12.2, @codemirror/language-data 6.5.2, react 19.3.1, zustand 5.0.15, vite 8.3.4, @vitejs/plugin-react 6.1.2, esbuild 0.28.2, typescript 5.9.3 (last 5.x; 7.0.2 is the native port), ws 8.22.0, chokidar 5.0.0. `docent-ide` is free on npm; `docent`, `kibitz`, `understudy`, `glassbox`, `footnote` are taken. |
| env | spawning `claude` from inside another Claude Code session | **Finding.** The child inherits a `CLAUDE_CODE_CHILD_SESSION` marker that turns transcript saving off (`⚠ Transcript saving is off`). Docent's spawn env deletes `CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_CHILD_SESSION` and `CLAUDE_CODE_SSE_PORT` before setting its own. |
| trust | workspace trust | **Finding.** A folder never opened before shows the trust dialog in the TUI ("Yes, I trust this folder"); the words are drawn with cursor moves, so any text match must strip escape sequences first. Docent lets the user answer it in the terminal. |
| `/ide` | the IDE picker | **Finding.** `/ide` lists every `~/.claude/ide/*.lock` (nine stale VS Code locks here), so Docent's lock shows up by `ideName`; stale locks of dead pids should be ignored, not deleted. |

## Install note (2026-10-19)

`"postinstall": "electron-builder install-app-deps"` in `packages/app` recursed under npm workspaces: install-app-deps spawns `npm install`, which runs the workspace postinstall again (765 nested installs before it was killed). Removed. It is not needed anyway: node-pty 1.1.0 ships N-API prebuilds (`prebuilds/<platform>-<arch>/pty.node`) that load unchanged inside Electron, so `npmRebuild` is off in `packages/app/electron-builder.yml` and the only post-install step is the spawn-helper exec bit (`scripts/postinstall.mjs`).
